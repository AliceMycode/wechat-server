# 群文件下载权限校验笔记

> 日期：2026-11-04
> 触发问题：群主踢了 B 之后，B 在界面上还能打开群里的文件——这段群成员校验到底有没有生效？该怎么验证？
> 涉及代码：`ChatMessageServiceImpl.downloadFile`、`ChatController.downloadFile`
> 对照前端：`D:\download\easychat-front\src\main\file.js`

---

## 0. 服务端校验逻辑

`ChatMessageServiceImpl.downloadFile`（249-261 行）：

```java
// 退群/被踢时 user_contact 是物理删除的，这里查不到 → 600
if (UserContactTypeEnum.GROUP.getType().equals(message.getContactType())) {
  Long contactCount = userContactMapper.selectCount(
    new LambdaQueryWrapper<UserContact>()
      .eq(UserContact::getUserId, userInfoDto.getUserId())
      .eq(UserContact::getContactId, message.getContactId())
      .eq(UserContact::getContactType, UserContactTypeEnum.GROUP.getType())
      .eq(UserContact::getStatus, UserContactStatusEnum.FRIEND.getStatus()));
  if (contactCount == null || contactCount == 0) {
    throw new BusinessException(ResponseCodeEnum.CODE_600);
  }
}
```

四个条件同时满足才算有权限：

| 条件 | 含义 |
|---|---|
| `user_id = 我` | 查我自己的关系记录 |
| `contact_id = 消息所属群` | 是这一个群 |
| `contact_type = 1` | 群关系（排除误匹配单聊） |
| `status = 1` | 正常在群（排除已解散的 2） |

退群/踢人是**物理删除** `user_contact` 行，所以被踢的 B 查不到任何记录 → `contactCount == 0` → 600。

接口参数（`ChatController:102-104`）：`fileId`（数字时当 messageId）、`showCover`（Boolean）。

## 1. 为什么界面上看起来"没拦住"

**前端是本地磁盘优先的**，`file.js:211-225`：

```js
expressServer.get('/file', async (req, res) => {
    const localPath = await getLocalFilePath(partType, showCover, fileId);
    if (!fs.existsSync(localPath) || forceGet == "true") {
        await downloadFile(fileId, showCover, localPath, partType);   // ← 只有本地没有才请求服务端
    }
    ...
    fs.createReadStream(localPath).pipe(res);   // ← 直接从本地磁盘读给界面
})
```

图片/视频/文件第一次点开时从服务端下载到本地（`localFileFolder/yyyyMM/messageId.后缀`），之后每次都直接读本地磁盘。

所以：**只要 B 在被踢之前点开过那个文件，被踢后再点就是纯本地读取，服务端的校验根本没有执行。**

---

## 2. 正确的验证方式

### 方式一：用 B 没点开过的文件

1. 群主在群里发一个**新**文件（B 从未点开过）
2. 群主踢掉 B
3. B 点这个新文件 → 本地无缓存 → 请求服务端 → `downloadFile` 抛 600 → 前端收到 `content-type == "application/json"` 时显示 `404.png`

### 方式二：直接打接口（最干净）

用 B 的 token，拿一条群消息的 `messageId`：

```bash
curl -i -X POST "http://localhost:5050/api/chat/downloadFile" \
  -H "token: <B的token>" \
  -d "fileId=<群消息messageId>&showCover=false"
```

| 状态 | 响应 |
|---|---|
| 踢之前 | `200` + 二进制流（`content-type: application/x-msdownload`） |
| 踢之后 | `application/json` + `{"status":600,...}` |

前端靠响应头 `content-type` 是不是 JSON 来判断"下载失败"，所以任何异常都必须走 `GlobalExceptionHandler` 返回 JSON。

---

## 3. 本地缓存仍可访问是正常设计

B 被踢后：

- **已缓存到本地的文件仍然能打开**：缓存的是 B 在被踢之前就有权访问的内容，离线数据本来就在他电脑上，不算服务端漏洞。
- **本地 SQLite 里的群历史消息也会留着**：前端不会因为收到 12 号消息就删本地会话。
  - `wsClient.js:121` 只有 11 号（自己主动退群）才 `break`，12 号（被踢）仍会推给渲染进程。

服务端校验真正拦住的是：**被踢之后去获取新的、存在服务端上的文件**。

| 问题 | 答案 |
